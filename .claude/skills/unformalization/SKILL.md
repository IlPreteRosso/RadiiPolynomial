## 1. The artefact and its invariants

The user's ask (2026-10-10, CONTRACT.md lines 5–8): for every `.lean` file that constitutes the
library API (not `Examples/`, not `tmp`, not import-only hub files), ship a complementary
unformalized `.tex` with its compiled `.pdf`, mirroring the directory structure.

Invariants (CONTRACT §1–§3; each is gate-checked or checker-checked):
1. **Mirror tree, one companion per API file.** `<LAKE>/RadiiPolynomial/<Dir>/<File>.lean` ↦
   `<UNF>/<Dir>/<File>.tex` + `.pdf`; build artefacts stay next to them, never versioned. Scope =
   `API_FILES.txt` (129 files), generated by `_tools/inventory.py` (a file with zero regex-matched
   declarations is a hub and is out of scope).
2. **Header pin = library commit.** `\unfheader{<source path>}{<7-char sha>}{<imports>}{<role>}{<importers>}`;
   the second field is the library revision the companion describes (5d0fa4f at campaign close,
   d6fda60 after the re-pin). `repin_finalize.py` swaps exactly this field.
3. **"Which object means what and in which place"** (user rule for talk notes, 2026-10-07, quoted in
   CONTRACT line 12): a Setting with standing hypotheses and a Who-is-who longtable (Lean object →
   symbol → meaning), body sections in file order, one numbered environment per public authored
   declaration, an index longtable at the end. The companion adds nothing the file does not prove.
4. **Effective binders, not section variables.** Hypotheses are the declaration's ELABORATED
   signature from the sidecar `_sidecar/<Dir>/<File>.sig.tsv` (Lean `PrettyPrinter.ppSignature`;
   unused section variables are omitted). Witness of record: `NewtonLikeMap.differentiable` carries
   no completeness although its section declares it (CONTRACT §2).
5. **Proof = the route the Lean proof establishes** (case split, auxiliary inequalities, instantiated
   theorems); tactic bookkeeping dropped; `simp` is never "compute" (name the lemmas; probe with `simp?`).
6. **Evidence taxonomy** for anything not proved in this file: `\evidl{Lean: <Dir/File.lean>}{name}`,
   `\evidl{Mathlib}{name}`, `\evidl{LeanCert}{name}`, `\evidl{Lean core}{name}` (each name resolved
   by a real `#check` through `_tools/resolve_external.py` into `_sidecar/EXTERNAL_RESOLVED.txt`),
   and `\evid{not formalized here}` — only in Remarks, meaning "no supporting declaration identified
   in the audited scope", never a global absence claim.
7. **Names only in the PDF, binders in the sidecar.** `\lean{…}` = declaration names, byte-exact,
   never in headings or math; `\leanx{…}` = binders, expressions, paths, tactic names. No code blocks.
8. **Trust boundary sentence** in every Setting (§7.26/§7.30 wording of record).
9. **Freeze binds everything.** `_records/<unit>/MANIFEST.json` = library HEAD + porcelain + toolchain
   + dependency revisions + sha256 of each source, sidecar, olean, tex, pdf, log, the contract, style,
   tools and registries; per-unit frozen copies of contract, style and both registries.

Macros a companion uses (`_common/unformalization.sty`; every companion starts
`\documentclass[11pt]{article}\usepackage{unformalization}`, no other packages, only local
`\newcommand`s): `\lean{Name}` (catcode trick: `_`, `.`, `'` active, breaks after `_` and `.`),
`\leanx{…}` (plain `\texttt`, escape `\_`, unbreakable — break by hand with `\allowbreak`, §7.70),
`\evidl{<tag>}{<name>}` (starts with `\unskip\ `; never parenthesise it, §7.25), `\evid{…}`,
`\leanline` (`\par\nopagebreak\noindent\emph{Lean.}\ `), `\bookref{…}` (prints `[Book, …]`,
attribution only), `\unfheader{5 args}`, `\unftitle{A.B.C}` (title path breakable after dots, §7.31),
`\unfpath`, `\fpath` (= `\nolinkurl`), `\verdict`. Reserved symbol macros: `\R \N \Q \C \Z \nrm
\abar \lnu \Hom \diag \ev` (§7.47). Environments: theorem, lemma, proposition, corollary, fact
(plain); definition, example, convention (definition style); remark. Typewriter ligatures are off.

## 2. Pipeline per unit (who does what, in order)

Roles (CONTRACT §5 + HANDOFF §4 + memory `feedback_subagent_model.md`): **Fable coordinates only**
(rulings, briefs, hand-checks, small residual edits); **Opus 5.5** = drafters, checkers, fixers,
re-pin drafters/checkers (judgment units; checkers at effort high per the subagent-model note);
**Haiku 5.5, effort medium** = recipe-plus-script steps (`freeze.py`, `repin_finalize.py`), with
the coordinator hand-checking the first MANIFEST; **Codex** (peer on the agents bus) = audit of the
sampled units. Pin the model on every Agent call; ≤ 5 agents in flight; never terminate a fired agent.

Stage 0 — set-up (once per campaign; coordinator):
1. Scope: `(cd $UNF && python3 _tools/inventory.py)` → `API_FILES.txt`, `INVENTORY.md`, `UNITS.md`,
   `_tools/units.json` (directory-family units, ≤ 8 files, ≤ 3600 lines).
2. Launch units: merge small UNITS into launch units by hand → `LAUNCH_UNITS.md` +
   `_tools/launch_units.json` (`[{"unit","from","files"}]`). No tool writes this file (UNSETTLED: the
   merge was done by the coordinator; the procedure is not recorded beyond "merged from UNITS.md").
3. Sidecars: `(cd $UNF && python3 _tools/signatures.py)` (all launch units; needs CURRENT oleans; no
   build) → `_sidecar/<Dir>/<File>.sig.tsv` + `_sidecar/ALL_FQNS.txt`.
4. Tool self-test: `(cd $UNF && python3 _tools/selftest.py)` → `SELFTEST PASS` (8 negative controls).
5. Contract + style frozen for the wave; a PILOT unit first (E1 Core was the pilot; its checker's
   rulings became §7.1–7.11 before wave 1). Codex reviewed the contract before wave 1 (seven positions).

Stage 1 — DRAFTER (one Opus per launch unit; brief `_briefs/<unit>_DRAFTER.md`, template in
`references/brief_templates.md`). Reads CONTRACT.md in full, the sidecars, the house exemplars
(`Core/Bounds.tex`, `Core/Theorem.tex`), UBIQUITOUS_LANGUAGE.md, ARCHITECTURE.md, then the sources.
Preconditions before building (§8 P1–P4): move every property out of Definition environments into a
following Lemma/Fact; confirm every "the proof uses X" sentence against the proof text and PROBE every
substantive `simp`/`rw` route (§7.55; probe files under `_records/<unit>/probes/`); check every
description of an external definition on its whole domain (§7.58); grep for unused privates (§7.54).
Done =, per file, in this order:
   `python3 _tools/build.py <Dir/File.tex>` → `OK`; `python3 _tools/resolve_external.py <Dir/File.lean>`
   (STILL UNRESOLVED names are misspelt: fix, never allow-list); `python3 _tools/gates.py <Dir/File.lean>`
   → `n/n pass`. Obstacles go into the final report, not improvised around.

Stage 2 — CHECKER (one Opus per unit, READ-ONLY except its own matrices; `CHECKER_TEMPLATE.md` plus a
unit line and focus items from the drafter's report). Writes `_records/<unit>/MATRIX_<File>.md`, one
row per sidecar declaration in sidecar (= source) order: FQN (span) | effective hypotheses | conclusion
matches? | proof route matches? | exposition label | verdict. Reads every rendered page. Probes
`simp?`/`#check`/`pp.explicit` on scratch files (§7.36, §7.32, §7.53). Reply = findings table
(ID, severity ERROR/MAJOR/EVIDENCE/MINOR, file, verbatim anchor, problem, replacement) + one verdict
per file (ACCEPT / FIX n). Rulings first: a checker raises only points no §7 ruling covers (§8).

Stage 3 — COORDINATOR RULING. Save the hand-back verbatim with
`python3 _tools/handback_extract.py <task-output.jsonl> <marker> _records/<unit>/FINDINGS_checker_round1.md`
and prepend the rulings ("apply all n as written", plus coordinator items, plus any new §7 ruling).
A new ruling is appended to CONTRACT §7 but reaches running drafters only through the next brief.

Stage 4 — FIXER (Opus; the drafter or a fresh Opus with the FINDINGS file). Applies every finding of
every severity (§7.5: every class is fixed before the freeze), records the disposition of each,
rebuilds, re-resolves new external names, gates → `n/n pass`.

Stage 5 — NARROW RECHECK (Opus) when the round had an ERROR or MAJOR (also run in most other units:
16 of 26 had a recheck). One-word leftovers may be applied by the coordinator.

Stage 6 — FREEZE: `(cd $UNF && python3 _tools/freeze.py <unit>)` → `frozen <unit>: n files; MANIFEST
sha256 <16 hex>`. Refuses when any gate fails or a unit source is modified in the library working tree.
Haiku may run it; the coordinator hand-checks the first MANIFEST (`library_head`,
`library_source_porcelain` == ""). The 8-hex prefix of the MANIFEST sha is the freeze id in PROGRESS.

Stage 7 — CODEX AUDIT for the sampled units only (E1 Core, B9 WeightedL1, D2 Certification/IVP,
E4 Tactic; first expansion candidate by defect pattern: B4 Spectrum). Request via the agents bus
(agents-bus skill). CHANGES → fixer → re-freeze (keep the audited manifest as
`MANIFEST_round<k>_<sha8>.json` / `MANIFEST_accepted_<sha8>.json`) → ACCEPT. Sampling never means
"Codex audited all files"; no unit is accepted by being named a sample.

Stage 8 — DELIVER the PDFs to the user (the campaign used SendUserFile) and rewrite the unit's row in
`_records/PROGRESS.md`.

Defect profile to expect (PROGRESS + FINDINGS): one ERROR in 26 units (E4 AutoPolyFDeriv, a Convention
wording); MAJORs came from (a) a property smuggled into a Definition (§7.5: C2 S1, C5 T3, D3 P-1),
(b) a route sentence a probe refuted (C5 T1 `simp` at k=0; C4 O1 unused private helper), (c) an
external definition described beyond its domain (D1 `ofIntervalRat`, p>0; §7.58). Hence P1–P4.

## 6. Traps and lessons

Tool bugs caught by drafters/checkers/Codex (all fixed in the current tools; memory note + §7):
- notation names `«term_⋆[_]_»` need an atomic tokenizer (§7.12); an `.eq_` filter dropped real
  `eq_*` theorems — only `eq_<digits>`, `eq_def`, `eq_unfold` are equation lemmas;
- Mathlib `export` aliases resolve only by their declared name (§7.13); Lean-core names must be
  tagged `Lean core` and resolve to `Init.`/`Lean.`/`Std.` modules (§7.16);
- `findDeclarationRanges?` needs the mangled private name, `privateToUserName?` for display;
  sidecar kind `structure` vs `inductive` (§7.27); congr_simp provenance probes need
  `Environment.contains n (skipRealize := false)` (§7.50);
- the shared growing `EXTERNAL_RESOLVED.txt` drifts between freeze and acceptance → per-unit
  `*.frozen.txt` copies (Codex); freeze once listed its own frozen copies among `checker_records`
  (self-inconsistent manifest) → excluded; CONTRACT/style also drift → `CONTRACT.frozen.md`,
  `unformalization.frozen.sty` per unit (Codex B9);
- concurrent drafters raced on the registry → exclusive `fcntl` lock (§7.33); one Lean process per name
  was slow → batched per cited module (§7.64);
- stranded Lean lines at a page top → `\leanline` carries `\nopagebreak` + gate G8; G10 advisory notes
  are printed, never fail (§7.66); G10 misses bare Mathlib suffixes (logged, unchanged).
Process lessons:
- NEVER change contract, style or tools under a running drafter; changes are announced in the next
  wave's briefs (§6). One drafter read a stale contract copy after §7.51–55 were appended mid-wave.
  New rulings DO apply to units still open at check/fix time (C5 FINDINGS, contract point 1).
- Rulings first: half of the round-1 findings of waves 2–3 relitigated points already ruled (§8).
- `freeze.py` refuses modified sources: a re-pin cannot freeze before the user commits the library.
- Brief summaries are hints; the drafter follows the source and reports the discrepancy (§7.43).
- Subagent hand-backs: save with `handback_extract.py` from the task JSONL; never read the JSONL by hand.
- Sibling subagents share the session scratchpad root: give each worker a private subdirectory.
- zsh: `command /usr/bin/grep` (bare `grep` is a wrapper that hangs on recursive greps); never a
  top-level `cd` — subshell `(cd <dir> && cmd)`; never chain pdflatex passes with `&&` (build.py does
  three passes itself); `${=var}` to word-split.
- Lean: never `lake build` inside the unformalization work (sidecars and probes use `lake env lean`
  on existing oleans); never `lake --dir` (wrong toolchain); never rebuild Mathlib. Library builds are
  the library side's job, from the Lake root in a subshell.
- The harness classifier refused edits of UBIQUITOUS_LANGUAGE.md twice → write the replacement to a
  file for the user (`_records/docstring_sweep/GLOSSARY_FIXES.md`); it also flags some multi-command
  Bash lines as destructive — split them. The Edit tool needs a prior Read.
- Commits, merges, installs are the user's; never `git checkout --`/`reset --hard`/restore/stash;
  library-side workers may run only `git status --short` and `git diff -- <file>`.

## 7. What is RadiiPolynomial-specific vs generic

Generic (carry over to any Lean 4 library): the contract structure (§2 template, §3 evidence
taxonomy, §4 gates, §5 pipeline, most §7 rulings), the sidecar extraction from compiled oleans, the
